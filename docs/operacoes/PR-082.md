# PR 082 — nós de fila, espera humana e encerramento

## Implantação

1. Aplicar a migration `20260901013000_espera_atendente_fluxo`.
2. Implantar API e todas as instâncias de `worker_fluxos` com a imagem PR 082.
3. Confirmar `/api/v1/saude/pronto` como `PRONTO`, migration vigente e imagens homogêneas.
4. Publicar os novos nós somente depois de cadastrar filas internas ativas e validar a topologia completa.

## Aceite

- transferir atendimento BOT para fila ativa com uma atribuição aberta e auditoria `FLUXO` sem usuário/sessão;
- negar fila inativa, autoridade humana, execução/versão divergente e topologia incompatível sem efeito parcial;
- persistir `AGUARDANDO_ATENDENTE`, marcador protegido e timeout futuro;
- reiniciar workers e comprovar uma única retomada pelo PostgreSQL;
- comprovar que resgate humano suspende a execução e que timeout segue a saída nominal;
- encerrar pela máquina de atendimento, congelar fila de fallback e concluir a execução no próprio nó;
- comprovar ausência de motivo e dados de cliente em passo, evento, auditoria e logs.

## Recuperação

Não alterar atribuição, histórico, marcador, `retomar_em`, estado, nó ou revisão por SQL. Reiniciar workers homogêneos reconstrói timeout vencido. Corrigir fila ou definição em nova versão. Rollback preserva estados e histórico; antes de usar worker PR 081, comprovar que nenhuma execução não terminal depende dos nós desta PR.
