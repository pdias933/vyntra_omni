# PR 112 — deploy compatível

## Pré-condições

- branch publicada, portões locais verdes e identificador de release imutável;
- imagem anterior preservada e compatível com todas as migrations aditivas;
- backup válido conforme PR 113 antes de produção;
- PostgreSQL, Redis, Object Storage e proxy saudáveis;
- Docker local; o script recusa contexto remoto.

## Publicação

```text
VYNTRA_RELEASE=<release> \
VYNTRA_RELEASE_ANTERIOR=<anterior> \
VYNTRA_CONFIRMAR_DEPLOY=PUBLICAR_<release> \
pnpm deploy:staging publicar
```

O script valida a composição, constrói as imagens, executa exatamente um job efêmero de migration, ativa API/web e duas réplicas do worker aguardando saúde, atualiza o proxy e faz smoke privado de prontidão. Falha após a migration tenta reativar o release anterior; schema não é desfeito.

## Drenagem

1. API muda prontidão para indisponível.
2. Registro central completa SSE e o gateway fecha WebSocket para reconexão.
3. Nest encerra servidor e recursos em até 15 segundos; o contêiner concede 25.
4. Worker acorda ao sinal, termina o ciclo corrente, não adquire outro e recebe 30 segundos.
5. Clientes retomam pela última `sequencia_evento` aplicada; PostgreSQL continua autoridade.

## Reversão

```text
VYNTRA_RELEASE=<release-com-falha> \
VYNTRA_RELEASE_ANTERIOR=<anterior> \
VYNTRA_CONFIRMAR_DEPLOY=REVERTER_<release-com-falha>_PARA_<anterior> \
pnpm deploy:staging reverter
```

Confirmar prontidão, versão e digest das imagens anteriores. Não executar migration na reversão, não remover objetos e não editar a tabela do Prisma.
