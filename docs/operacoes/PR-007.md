# PR 007 — correlação, logs e saúde

## Endpoints

```text
GET /api/v1/saude/vivo
GET /api/v1/saude/pronto
```

`vivo` confirma somente que o processo e o event loop atendem HTTP. `pronto` verifica que a configuração mínima existe nos ambientes estritos e tenta conexão TCP, em paralelo e com timeout de um segundo, com PostgreSQL, Redis e storage. A resposta pública não revela qual componente falhou.

Desenvolvimento, staging e produção falham fechados quando uma dependência obrigatória não foi configurada. O Docker Compose usa `pronto` para decidir saúde e só publica a API depois de PostgreSQL, Redis e storage estarem saudáveis.

## Correlação

Cada requisição recebe `correlacao_id` UUID. Um `x-correlation-id` recebido só é preservado quando tem formato UUID válido; qualquer outro valor é descartado e substituído. O identificador volta no header e em todo erro canônico, e acompanha logs dentro do contexto assíncrono da requisição.

## Logs

Pino escreve JSON em stdout/stderr para a rotação do Docker. Campos técnicos iniciais: evento, correlação, módulo, operação, método/status HTTP, duração e código de erro. O logger não recebe corpo, query, headers ou dados de cliente. Sanitização central remove campos fora da allowlist e mascara padrões sensíveis antes da serialização.

## Limites desta PR

- na entrega da PR 007, readiness ainda não executava query autenticada nem conferia migration; a PR 008 passou a confirmar a migration obrigatória via cliente persistente;
- métricas e OpenTelemetry permanecem para PRs posteriores;
- auditoria é persistente e separada de log técnico; entra na PR 008.

## Aceite em staging

Em 31 de agosto de 2026, a imagem `vyntra/api-staging:pr-007` foi construída e implantada na VM a partir da branch publicada. Vivacidade e prontidão responderam `200`; correlação UUID válida foi preservada, valor inválido foi substituído e o mesmo identificador apareceu no header e no erro canônico. O OpenAPI publicou os dois endpoints, as linhas recentes do processo foram validadas como JSON com evento/correlação e API, PostgreSQL, Redis e Garage S3 permaneceram saudáveis. Volumes e segredos exclusivos do staging foram preservados.
