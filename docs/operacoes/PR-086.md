# PR 086 — shell web e autenticação

## Implantação

- não há migration nem segredo novo;
- implantar web e API do mesmo commit para preservar os contratos de sessão e SSE;
- manter cookies `HttpOnly`, `Secure` e `SameSite` emitidos apenas pelo backend;
- confirmar que o proxy não armazena ou bufferiza `/api/v1/sincronizacao/eventos`.

## Aceite

1. Usuário sem sessão vê somente o login e não recebe conteúdo operacional.
2. Login válido abre o shell; credenciais inválidas não permitem enumeração.
3. A terceira sessão exige confirmação antes de substituir a mais antiga.
4. Expiração ou revogação retorna ao login sem conservar conteúdo protegido.
5. `PERMISSOES_ALTERADAS` provoca revalidação da sessão e do escopo.
6. Navegação por histórico preserva rotas de atendimento, administração, fluxos e saúde.
7. Nenhum token ou senha é persistido em storage do navegador.

## Reversão operacional

Reverter somente a imagem web é seguro, pois a PR não altera o PostgreSQL. Sessões emitidas continuam sob autoridade do backend e podem ser revogadas normalmente.
