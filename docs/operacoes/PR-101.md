# PR 101 — lista de atendimentos mobile

## Escopo operacional

A entrega ativa a aba `Atendimentos` sobre uma projeção local autorizada. Não publica binário em loja, não cria serviço novo e não altera o PostgreSQL. O SQLite criptografado avança para `user_version = 3`.

## Antes de distribuir

1. Confirmar que a API e a build pertencem ao mesmo commit.
2. Confirmar a configuração de chave pública da autorização offline da PR 099.
3. Executar lint, tipos, testes, contratos, matriz Expo, dependências, segredos e builds iOS/Android.
4. Validar em Development Build a atualização automática, os seis filtros e “Reduzir Movimento”.

## Aceite funcional

- O filtro inicial é `Meus`; os demais são `Pendentes`, `Não lidos`, `SLA`, `Expirando` e `Em automação`.
- Não existem cards-resumo, atualização manual, timestamp de sincronização ou indicador técnico saudável.
- Um snapshot novo altera prévia, contagem e ordem automaticamente, mantendo `conversa_id` como chave visual.
- `SEM_CONEXAO`, `CONECTANDO` e `SINCRONIZANDO` exibem somente a faixa temporária correspondente.
- A ativação de “Reduzir Movimento” elimina a transição de posição sem atrasar os dados.
- A migration 2→3 marca a réplica como suja e exige snapshot completo antes de permitir leitura offline.

## Observação e rollback

Observar apenas métricas agregadas de duração/tamanho de snapshot, reconstruções e latência de leitura local. Nunca registrar conteúdo da prévia, nome, telefone, contato, conversa ou autorização offline.

Para rollback, distribua uma build compatível com `user_version = 3`. Se isso não for possível, descarte a réplica criptografada e reconstrua-a pelo servidor; rascunhos e pendências devem passar pelo fluxo explícito de reconciliação. Não altere a versão do schema manualmente.
