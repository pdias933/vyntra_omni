# PR 099 — SQLite e autorização offline

## Objetivo e limite

Esta entrega cria a réplica SQLCipher, custodia sua chave no SecureStore, emite autorização offline Ed25519 somente para snapshot mobile e bloqueia o cache diante de prazo, vínculo, assinatura, integridade ou relógio inválidos. Não aplica ainda o snapshot nem inicia WebSocket; a transação de sincronização pertence à PR 100.

Não há migration PostgreSQL. O schema SQLite local nasce em `user_version = 1` e pode ser descartado/reconstruído porque o PostgreSQL continua sendo a fonte da verdade; rascunhos e pendências terão reconciliação explícita nas PRs 100 e 104.

## Configuração por ambiente

A API exige:

```text
AUTORIZACAO_OFFLINE_CHAVE_ID=<identificador versionado>
AUTORIZACAO_OFFLINE_CHAVE_PRIVADA_FILE=/run/secrets/chave_autorizacao_offline
```

A build mobile do mesmo ambiente exige um JSON de chaves públicas:

```text
EXPO_PUBLIC_CHAVES_AUTORIZACAO_OFFLINE={"<identificador>":"<chave-publica-base64url>"}
```

Nos ambientes versionados, preparar e obter somente a configuração pública:

```text
pnpm ambiente:preparar
pnpm ambiente:configuracao-mobile

pnpm staging:preparar
pnpm staging:configuracao-mobile
```

O segundo comando imprime apenas a chave pública. O arquivo PEM privado permanece em `.segredos/<ambiente>/chave-autorizacao-offline.pem`, modo `0640`, montado somente na API e ignorado pelo Git. Não copiar chave entre desenvolvimento, staging e produção.

## Rotação sem interromper autorizações vigentes

1. gerar nova chave no cofre e escolher novo identificador;
2. publicar build que aceite simultaneamente as chaves públicas antiga e nova;
3. trocar arquivo privado e identificador da API, confirmando que novas autorizações usam a chave nova;
4. esperar pelo menos quatro horas desde a última emissão antiga;
5. publicar build posterior retirando a chave pública antiga e eliminar o material privado antigo segundo a política do cofre.

Nunca reutilizar identificador para outro par. Se a chave privada for perdida, novas sincronizações completas mobile falham fechadas; restaurar do cofre ou executar rotação. Se houver suspeita de vazamento, interromper emissões, distribuir build sem confiança na chave comprometida e elevar a política mínima conforme o processo de incidente.

## Aceite

1. API assina Ed25519 e limita a validade ao menor valor entre quatro horas e o refresh;
2. snapshot web não recebe token offline;
3. app rejeita chave desconhecida, payload adicional, assinatura alterada, usuário/sessão/dispositivo/instalação divergentes, expiração e recuo do relógio;
4. SQLCipher recebe chave antes de qualquer leitura, passa por verificação de integridade e usa parâmetros para dados;
5. login novo, QR concluído e logout não reutilizam dados autenticados anteriores;
6. configuração pública deriva da chave privada sem exibi-la ou sobrescrevê-la;
7. todos os portões obrigatórios do repositório passam.

## Implantação e reversão

Não implantar a API nova antes de provisionar a chave privada e distribuir uma build mobile com a chave pública correspondente. A ausência de chave afeta somente a emissão do snapshot completo mobile e deve falhar fechada; não criar fallback sem assinatura.

Reverter API e app em conjunto quando ainda não houver réplica preenchida pela PR 100. Depois que a PR 100 for entregue, uma reversão deve preservar no app a chave pública necessária até vencer a última autorização emitida e manter compatibilidade com `user_version = 1` ou descartar a réplica de forma segura.

- assinatura Ed25519 real foi verificada e os vínculos, escopos mínimos, sequência base e limite pelo refresh foram testados;
- geração preservou a chave existente, validou tipo/permissão e derivou somente a chave pública mobile;
- SQLCipher, cofre, schema, limpeza e bloqueio offline foram cobertos pelos testes de arquitetura;
- lint e tipos de todo o workspace passaram;
- 432 testes da API e 261 testes de arquitetura passaram;
- matriz Expo e auditoria de dependências passaram; o advisory transitivo de `qs@6.15.3` foi eliminado por `6.16.0` sem allowlist;
- Gitleaks 8.30.0 examinou 223 commits e a árvore alterada sem encontrar segredo;
- builds de API, web, iOS e Android passaram.
