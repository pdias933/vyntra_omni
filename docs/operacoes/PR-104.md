# PR 104 — offline e reconciliação mobile

## Escopo operacional

A entrega cria pendência criptografada de texto offline, sincroniza antes da tentativa, compara no backend toda a observação relevante e separa envio automático de revisão humana. Não inclui mídia offline, ação ERP offline, migration PostgreSQL, dependência, deploy ou publicação nas lojas.

## Distribuição

1. Gerar OpenAPI/SDK e distribuir API e app a partir do mesmo commit.
2. Confirmar `user_version = 4`; nunca executar downgrade manual do SQLCipher.
3. Validar a chave pública e o prazo da autorização offline da build.
4. Exercitar sessão, dispositivo e permissão revogados entre criação e reconciliação.
5. Manter a mídia offline desligada.

## Matriz mínima de aceite

- sem mudança: sincroniza, reconcilia uma vez e entra em `NA_FILA`;
- evento de entrada ou saída web posterior: `REVISAO_NECESSARIA`;
- transferência e retorno: revisão pela versão de atribuição;
- encerramento e reabertura: revisão pela versão de estado;
- troca e restauração de contexto: revisão pela versão de contexto;
- janela alterada ou expirada: revisão e nenhum texto livre automático;
- `401`/`403`: revisão por acesso alterado;
- timeout ou indisponibilidade: mantém `AGUARDANDO_CONEXAO`;
- `Editar`: volta ao rascunho atomicamente;
- `Descartar`: remove apenas a pendência escolhida;
- `Enviar mesmo assim`: cria novo comando e continua sujeito à autorização atual;
- `CONECTANDO`/`SINCRONIZANDO`: nenhuma tentativa de envio.

## Observação e rollback

Observar somente contagens por resultado, latência e códigos canônicos. Nunca registrar texto, IDs de contato/conversa/atendimento, token, segredo do aparelho ou valores observados.

Reverter API e app coordenadamente. Uma build anterior não deve abrir `user_version = 4`; use uma build compatível ou descarte a réplica autenticada e obtenha snapshot novo. Nunca reduza `user_version`, edite pendências por SQL operacional ou force mensagem como enviada.
