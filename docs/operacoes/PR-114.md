# PR 114 — testes integrados adversariais e de falha

## Portão adversarial

`pnpm test:adversarial` recompila a API e executa uma seleção nominal, reproduzível e bloqueante:

| Risco | Prova exigida |
|---|---|
| IDOR/BOLA | sessão, permissão, fila e recurso são avaliados antes do conteúdo; outro UUID/fila recebe negação canônica |
| webhook falso/replay | HMAC no corpo bruto, assinatura ausente/inválida e duplicidade não produzem persistência indevida |
| XSS/conteúdo ativo | React sem injeção de HTML, CSP sem script inline, PDF em iframe sandbox e resposta `nosniff` |
| upload hostil | tamanho, assinatura real, MIME, hash, bucket privado e alteração posterior são validados |
| perda Redis/worker | estado recuperável permanece no PostgreSQL e reinício não duplica efeito |
| lacuna/reinício de API | snapshot/cursor e SSE/WebSocket retomam pela sequência do servidor |
| corrida offline | autoridade, atribuição, contexto, estado, janela e timeline são comparados sob lock antes do envio |

O runner não substitui os testes completos; é um portão curto para promoção e investigação de regressão.

## Falhas controladas em staging

Depois do deploy, com janela comunicada, execute:

```text
VYNTRA_CONFIRMAR_TESTE_FALHAS=EXECUTAR_FALHAS_CONTROLADAS_STAGING node scripts/aceitar-falhas-staging.mjs
```

O ensaio reinicia Redis, interrompe e retorna o worker e reinicia a API, medindo o retorno da saúde pública. Ele não altera banco, volume ou DNS. Antes e depois, confira backlogs, ausência de efeitos duplicados, reconciliações e logs sanitizados.

Desligar/reiniciar a VM inteira não é automatizado de dentro da própria VM: a prova exige janela supervisionada, acesso ao console do provedor, monitor externo e operador capaz de reverter DNS ou restaurar em outro host. Esse ensaio continua bloqueante para produção, mas não para o deploy de staging. Não simular seu resultado em documentação.

## Resultado e resposta

Qualquer negação que revele a existência de recurso, execução duplicada, mídia ativa fora do sandbox, cursor perdido ou estado de negócio dependente do Redis reprova a release. Preserve correlação técnica e horários; nunca anexe corpo de webhook, mensagem, token, documento ou segredo à evidência.
