# PR125 — contexto operacional e resgate

Estado: EM ANDAMENTO. Effort recomendado: `xhigh`.

## Escopo implementado

Serviço compartilhado pelos consoles web/mobile, consulta `GET /atendimentos/:atendimentoId/operacao` e comando `POST /atendimentos/:atendimentoId/resgatar`, sob os dois prefixos existentes. SDK regenerado. Fila, ator e recurso são resolvidos no servidor. Consulta não produz resgate.

O comando usa autenticação transacional dos consoles e o mesmo lock `autoridade-saida` do domínio antes de resolver a fila. O SQL parametrizado é necessário porque Prisma não expõe advisory locks. Serviço de atribuições conserva versão, suspensão da automação, histórico, auditoria e evento. Registro idempotente, concessão e conclusão usam o mecanismo PostgreSQL existente na mesma transação. Repetição revalida a permissão e retorna somente confirmação, nunca conteúdo histórico.

Interfaces oferecem resgate explícito, bloqueiam offline e conservam a chave durante resposta incerta para nova tentativa manual. Não há fila offline de operações. Grafite e tokens existentes são preservados.
