# Dependências do PR 002

O PR 002 instala somente ferramentas necessárias para compilar as três aplicações e executar as verificações da raiz. Não adiciona banco, integração, telemetria, estado remoto, UI compartilhada ou código de domínio.

| Grupo | Necessidade | Manutenção/licença | Superfície introduzida |
|---|---|---|---|
| Node.js 24 LTS, TypeScript e pnpm | Runtime, tipos e instalação reproduzível | projetos amplamente mantidos; licenças permissivas | execução de scripts locais e dependências de desenvolvimento |
| Turbo | Orquestrar os mesmos comandos nos workspaces | Vercel, licença MIT | cache e execução local; cache remoto e telemetria permanecem desabilitados |
| NestJS, RxJS e reflect-metadata | Backend definido em `ARCHITECTURE.md` | projetos ativos; licenças MIT/Apache-2.0 permissivas | servidor HTTP local vazio, sem endpoint de negócio |
| React, React DOM, Vite e plugin React | Web definida em `ARCHITECTURE.md` | projetos ativos; licenças MIT | bundle web estático sem comunicação externa |
| Expo, React Native, Development Build e expo-status-bar | Mobile definido em `ARCHITECTURE.md` | projetos ativos; licenças MIT | bundling nativo e cliente de desenvolvimento; nenhum módulo sensível instalado |
| ESLint, typescript-eslint e plugins React | Guardas de qualidade compartilhados | projetos ativos; licenças MIT | análise estática local |

As versões foram fixadas em 29 de agosto de 2026. Expo segue exatamente a matriz do template oficial SDK 57 (`expo ~57.0.18`, React 19.2.3, React Native 0.86.3 e TypeScript ~6.0.3). Reanimated e Gesture Handler não entram antes de existir uso real no PR mobile correspondente.

O projeto usa instalação `hoisted` porque esse é o padrão atual do `create-expo-app` com pnpm. Metro não recebe configuração manual; Expo SDK 57 detecta o monorepo automaticamente.

Os comandos da raiz passam pelo wrapper `scripts/executar-turbo.mjs`, que define `DO_NOT_TRACK=1` e `TURBO_TELEMETRY_DISABLED=1` de forma compatível com macOS, Linux e Windows. Isso evita coleta anônima por padrão sem adicionar dependência apenas para configurar ambiente.

Os comandos mobile passam de modo equivalente por `apps/mobile/scripts/executar-expo.mjs`, com `EXPO_NO_TELEMETRY=1`. O wrapper fica no workspace que declara Expo, sem depender de pacote transitivo da raiz. Ele não ativa `EXPO_OFFLINE`, pois instalação, bundling e desenvolvimento podem precisar consultar serviços explicitamente solicitados.

## Exceção conhecida da árvore transitiva

Em 29 de agosto de 2026, `pnpm audit --prod` informa `GHSA-w5hq-g745-h8pq` como vulnerabilidade moderada em `uuid@7.0.3`, trazido por `xcode` dentro das ferramentas de build do Expo. O problema atinge as APIs `v3`, `v5` e `v6` quando recebem buffer/offset externos. A versão de `xcode` instalada usa apenas `uuid.v4()` sem buffer controlado, e o pacote não participa do runtime da API nem do bundle de negócio.

Não foi aplicado override incompatível fora da faixa suportada pelo Expo. O PR 003 deve monitorar a correção upstream; vulnerabilidade alta/crítica ou mudança de uso bloqueia merge/release. Esta exceção moderada expira no primeiro upgrade do Expo que remover o caminho vulnerável e deve ser reavaliada até 29 de setembro de 2026 e antes de qualquer piloto, o que ocorrer primeiro.
