## Critérios de seleção

- origem oficial;
- versão exata, sem `latest` ou faixa flutuante;
- digest do índice compatível com Apple Silicon e runner Linux x64;
- licença registrada;
- nenhuma credencial embutida;
- atualização deliberada com nova consulta, build e smoke test.

Node e pnpm seguem as versões já congeladas no monorepo. `pnpm deploy --prod --legacy` é usado porque o workspace ainda não habilita `injectWorkspacePackages`; alterar essa opção agora afetaria também Expo/web sem necessidade.

Redis 7.2 permanece suficiente para BullMQ e para os usos previstos da V1. A linha 7.2 continua sob BSD-3-Clause conforme a matriz oficial. Upgrade de major exige PR próprio, compatibilidade e nova análise de licença.

## Risco MinIO

A imagem comunitária multiarch disponível é anterior a avisos de segurança de 2026 e não recebe manutenção. Ela não pode ser reutilizada em staging/produção nem com dados reais. O isolamento local e a execução sem root são mitigadores, não correção da vulnerabilidade.

AIStor corrigido exige licença própria. Esta PR não solicita, aceita, versiona ou simula uma licença. A escolha de storage mantido para staging é decisão obrigatória antes da PR 005, conforme [o runbook local](../operacoes/PR-004.md#exceção-restrita-do-minio).

## Atualização

Ao alterar uma imagem:

1. confirmar versão suportada e licença na fonte oficial;
2. obter o digest do índice OCI/Docker, não o manifest por arquitetura;
3. confirmar `linux/amd64` e `linux/arm64`;
4. atualizar Compose, Dockerfile, testes e este documento juntos;
5. construir a API, subir a pilha e repetir o teste de persistência/reinício;
6. executar varredura de vulnerabilidades de contêiner quando esse portão for introduzido.

Não existe dependência npm nova nesta PR.
