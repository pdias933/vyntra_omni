# Dependências — PR 015

## Adições mobile

- `expo-secure-store ~57.0.2`: custódia nativa de refresh token, identificadores e segredo de vínculo em Keychain/Keystore;
- `expo-crypto ~57.0.2`: UUID e 256 bits aleatórios no aparelho sem implementar criptografia própria.

As versões pertencem ao conjunto compatível publicado pelo Expo 57 usado no projeto. Ambas são módulos oficiais do ecossistema Expo, com licença MIT. Nenhuma amplia a superfície do backend, executa regra de domínio ou recebe credencial da Meta/MK.

`pnpm audit` passa a enumerar `expo-crypto > expo > ... > xcode > uuid@7.0.3` como um caminho adicional para a mesma exceção moderada já aprovada na PR 002. O pacote vulnerável, a versão, o sufixo, o uso e o prazo da exceção não mudaram; a allowlist foi ampliada somente para essa entrada oficial e continua validando cada segmento e o ancestral fixado no lockfile.

SecureStore protege custódia local, mas não torna o aparelho confiável: o backend continua validando usuário, dispositivo, sessão, expiração e segredo de vínculo. O access token não é persistido. Biometria, sincronização e cache offline não foram antecipados por essas dependências.

## Backend

Nenhuma dependência foi adicionada. Tokens usam `node:crypto`; concorrência e replay usam Prisma/PostgreSQL com advisory lock parametrizado e tabelas próprias. Redis não é fonte de verdade da sessão.
